# Master Skill: Project Initialization

You are initializing a new AI/CV project using the whet framework. This page holds the
initialization loop, the archetype list, and the shared structure; the deep dives hold the
full configuration file contents and the verification script.

## Initialization Process

1. **Ask the user for project details:**
   - Project name (e.g., "Face Detection System")
   - Project slug (auto-generate from name: "face-detection-system")
   - Package name (auto-generate: "face_detection_system")
   - Author name
   - Email
   - Description
   - Python version (default: 3.11)
   - Initial version (default: 0.1.0)

2. **Ask which archetype to use:**
   - pytorch-training-project
   - cv-inference-service
   - research-notebook
   - library-package
   - data-processing-pipeline
   - model-zoo

3. **Ask which optional skills to include:**
   - Weights & Biases (wandb)
   - MLflow
   - TensorBoard
   - ONNX export
   - Model evaluation (model-evaluation)

4. **Generate project using selected archetype**
   - Copy archetype directory structure
   - Substitute templated values (project_name, author, etc.)
   - Include only requested optional skills
   - Generate appropriate pixi.toml with dependencies

5. **Verify structure and files**
   - Ensure all required files present
   - Run initial linting checks
   - Initialize git repository

## Standard Directory Structure (All Archetypes Share)

Every project generated by the master skill shares a common directory layout. Archetypes
extend this base with additional directories specific to their purpose (e.g., `configs/`,
`notebooks/`, `docker/`).

```
{{project_slug}}/
├── .github/workflows/
│   ├── ci.yml                 # Lint, type check
│   └── test.yml               # Test suite
├── .gitignore
├── .pre-commit-config.yaml
├── pixi.toml
├── pyproject.toml
├── README.md
├── src/{{package_name}}/
│   ├── __init__.py
│   └── py.typed               # PEP 561 marker
└── tests/
    ├── __init__.py
    └── conftest.py
```

The `src/` layout is mandatory across all archetypes: it prevents accidental imports of
the local package during testing and enforces proper installation.

## Template Variables

These variables are substituted throughout all generated files during project
initialization. The master skill replaces every occurrence of `{{variable}}` with the
user-provided value.

| Variable | Description | Example |
|----------|-------------|---------|
| `{{project_name}}` | Human-readable name | Face Detection System |
| `{{project_slug}}` | URL/directory safe | face-detection-system |
| `{{package_name}}` | Python import name | face_detection_system |
| `{{author_name}}` | Author full name | Enrique G. Ortiz |
| `{{email}}` | Author email | ortizeg@gmail.com |
| `{{description}}` | Project description | A face detection system |
| `{{version}}` | Initial version | 0.1.0 |
| `{{python_version}}` | Python version | 3.11 |

## Conventions

1. **Pixi manages the environment** — `pixi.toml` replaces requirements.txt,
   environment.yml, and Makefiles; every command runs through `pixi run <task>`.
2. **src-layout, always** — plus a `py.typed` marker so downstream consumers get the
   annotations.
3. **pyproject.toml is the single source of truth** for metadata, ruff, mypy, and pytest.
4. **Loguru only** — never `print()` or `logging.getLogger()`.
5. **Pre-commit is non-negotiable** — hooks installed before the first commit.
6. **Ruff line-length 100, target py311**; MyPy `strict = true`.
7. **Coverage gate at 80%** via `--cov-fail-under=80`.
8. **Nothing is left templated** — a generated project contains no `{{` markers.

## Anti-patterns

- **Flat layout** (package at the repo root instead of `src/`) — lets tests import
  uninstalled code and hides packaging bugs.
- **Scaffolding with uv, pip, or conda** — the framework scaffolds projects with **pixi**;
  do not introduce a second environment manager into a generated project.
- **`print()` or stdlib `logging`** in generated code — the `T20` ruff rules will fail it.
- **Committing model weights or datasets** — `.gitignore` blocks `*.pt`, `*.onnx`,
  `data/raw/`; use object storage or an artifact registry.
- **Skipping the verification pass** — an unbuilt, unlinted scaffold hands the user a
  broken repo.
- **Leaving `{{variable}}` markers** in any generated file.
- **Using this skill on an existing codebase** — it initializes new projects only.

## Post-Initialization Checklist

After generating the project, the master skill verifies each of these items:

- [ ] All template variables replaced (no `{{` remaining in any file)
- [ ] `pixi install` succeeds
- [ ] `pixi run lint` passes
- [ ] `pixi run typecheck` passes
- [ ] `pixi run test` passes (placeholder tests)
- [ ] `.git` initialized
- [ ] Pre-commit hooks installed
- [ ] README.md populated with project details
